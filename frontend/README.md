# Web Archiver Frontend

Frontend source for the [Web Archiver server](../README.md): Alpine.js
components, Tailwind/DaisyUI styling, and the Askama templates that Axum renders.

This is **not a standalone single-page app**. The Rust server owns routing,
authentication, and data loading; this directory provides the assets and HTML
templates those routes use.

> Companion browser extension:
> [source and releases](https://github.com/zennozenith/web-archiver-browser-extention)
> · [Firefox Add-ons](https://addons.mozilla.org/en-US/firefox/addon/web-archiver)
> · Chrome/Chromium builds are available from the
> [GitHub Releases](https://github.com/zennozenith/web-archiver-browser-extention/releases)
> page and can be loaded as an unpacked extension.

## Prerequisites

- The [Vite+ CLI](https://viteplus.dev/) (`vp`) on your `PATH`:

  ```bash
  curl -fsSL https://vite.plus | bash
  ```

- A recent Node.js runtime. Vite+ can manage Node and package managers through
  `vp env` / `vp install`.
- The Rust server for the full application. Building only this directory
  produces static files, not a runnable app.

## Getting started

```bash
cd frontend
vp install
```

Build into the directory the server expects:

```bash
# From frontend/; this is what devenv sets for you.
OUT_DIR=../static/vite vp build
```

Then start the server from the repository root:

```bash
cd ..
cargo run
```

Open <http://localhost:8889/dashboard>.

`vp dev` is available for iterating on TypeScript and CSS with Vite's dev server,
but pages are rendered by Askama. Use the Rust server when you need to see real
data or exercise htmx requests.

### Static preview without the Rust server

Generate a placeholder-data copy of every page route:

```bash
cd frontend
vp run build:preview
```

This command:

1. Runs `vp build` into `preview/static/vite`.
2. Renders the Askama templates with placeholder data from
   `scripts/preview-data.mjs`.
3. Rewrites absolute asset and navigation URLs to relative paths.

Open `frontend/preview/index.html` directly in a browser. The generated tree is
self-contained, so it can also be served by any static file server. Because
browsers block ES modules on `file://`, use a static server when you want the
Alpine interactions to run too:

```bash
python3 -m http.server 4173 --directory frontend/preview
```

The `preview/` directory is generated and ignored by Git. Re-run
`vp run build:preview` after changing a template or a placeholder. Captured
HTML, screenshots, and thumbnails are not bundled; their `/api/...` links fall
back to the matching link detail page where possible.

### Why the build must run before cargo

Askama compiles templates from `static/vite/src/templates` (configured in
`askama.toml`). That directory is generated by this frontend build, so it must
exist before Rust compiles. The server's `build.rs` normally runs the frontend
task through devenv automatically.

## Build pipeline

1. `vite.config.ts` globs every `src/**/*.{js,ts,html}` file and registers it as
   a build input.
2. Vite bundles TypeScript and CSS, and processes each HTML template. Relative
   references such as `../../app.ts` and `../../app.css` are rewritten to hashed
   asset URLs.
3. Output is written to `OUT_DIR` (default `dist`; the project uses
   `../static/vite`) under the `/static/vite/` base path.
4. HTML templates land in `static/vite/src/templates`, where Askama finds them.
5. `build.rs` moves any `{% extends %}` tag to the first line of a generated
   template, which Askama requires for inheritance.
6. Rust embeds `static/vite/assets` and `static/vite/images` at compile time and
   serves `static/vite/vendored` from disk. Recompile the server after a frontend
   rebuild so embedded assets stay in sync.

Do not edit files under `static/vite` by hand — they are generated.

```text
frontend/
├── vite.config.ts          Build inputs, aliases, Tailwind plugin, OUT_DIR
├── tsconfig.json           Strict TypeScript configuration
├── public/
│   ├── images/             Static images copied into the build
│   └── vendored/           htmx and htmax builds (+ .br variants)
├── scripts/                Static-preview generator and placeholder data
├── preview/                Generated static preview (ignored by Git)
└── src/
    ├── app.ts              Alpine registration and startup
    ├── app.css             Tailwind, DaisyUI, theme and component imports
    ├── alpine/             Alpine components and magics
    ├── api/types.ts        Shared API types
    ├── styles/             Custom themes and component styles
    └── templates/          Askama templates
        ├── layouts/        app.html (sidebar shell), bare.html
        ├── components/     Sidebar, modals, theme switcher
        ├── library/        Library UI pages and HTMX fragments
        ├── archive/        Compact archive dashboard
        ├── fragments/      Small shared response fragments
        └── error.html
```

Path aliases: `@src` → `src/`, `@common` → `src/common/` (the alias exists in
`vite.config.ts`; create the directory if you need it).

## Template conventions

- Templates use Askama syntax: `{% extends %}`, `{% block %}`, `{% include %}`,
  `{% for %}`, `{% if %}`, and `{{ value }}`.
- Keep `{% extends "layouts/app.html" %}` as the first line. `build.rs` enforces
  this after the build, but keeping it first avoids confusing diffs.
- Partials start with an underscore (`_link_card.html`) and are included, not
  routed directly.
- Use `layouts/app.html` for normal sidebar pages and `layouts/bare.html` for
  minimal pages. The app layout expects the shared `page` context (sidebar
  collections, tags, counts, active section).
- `library/` is the main UI. `archive/` is the compact capture-history
  dashboard at `/archive`. HTMX-only responses belong in `library/_*.html` or
  `fragments/`.
- Pass data through the view structs in `src/web/view.rs` and template structs in
  `src/web/templates.rs`. Templates should not query the database.
- Pass server strings to JavaScript through `data-*` attributes, not by
  interpolating them into inline scripts.

### Adding a server-rendered page

1. Add the template under `src/templates/library/` (or another section).
2. Add an Askama struct in `src/web/templates.rs`.
3. Add the handler and view data in `src/web/pages.rs` / `src/web/view.rs`.
4. Register the route in `src/web/mod.rs`.
5. Run the frontend build, then `cargo run`.

## Alpine components

All components are registered in `src/app.ts`.

| Module                  | Registration    | Responsibility                                                  |
| ----------------------- | --------------- | --------------------------------------------------------------- |
| `alpine/magics.ts`      | `$ok` magic     | True when an htmx request finished with status < 400            |
| `alpine/theme.ts`       | `themeSwitcher` | Theme selection, applied before paint and saved in localStorage |
| `alpine/toasts.ts`      | `toastRegion`   | Auto-dismiss server-rendered alerts after 8 seconds             |
| `alpine/tag-editor.ts`  | `tagEditor`     | Inline tag rename, reading the current name from `data-name`    |
| `alpine/page-filter.ts` | `pageFilter`    | Client-side filtering of cards by lower-cased `data-search`     |
| `alpine/link-view.ts`   | `linkView`      | Grid/list toggle persisted in localStorage                      |
| `alpine/reader.ts`      | `reader`        | Reader panel, text size, format, and selection state            |

To add a component, create a module that exports `registerX(alpine: Alpine)`,
then import and call it in `src/app.ts`.

## htmx conventions

- htmx 4 is loaded from `/static/vite/vendored/htmx-4.0.0.min.js`, so the UI
  works offline and without a CDN.
- The app shell sends the CSRF header through
  `hx-headers:inherited='{"X-CSRF-Token": "{{ page.csrf_token }}"}'`. The current
  single-user build uses a placeholder token; keep the hook if authentication is
  added later.
- The server decides whether to return a full page or a fragment based on
  `HX-Request` / `HX-Request-Type` (see `src/htmx.rs`). Responses set `Vary` so
  caches do not mix the two representations.
- Use `$ok($event)` in `@htmx:after:request` handlers before resetting a form or
  closing a dialog.
- Prefer `hx-target`, `hx-swap`, and the server's `HX-*` response headers over
  hand-written fetch calls.

## Styling and themes

- `src/app.css` imports Tailwind, registers the DaisyUI plugin, and loads custom
  themes and component styles.
- DaisyUI ships `light` and `dark`; the four custom themes (`minimaltide`,
  `chillecho`, `lastpickle`, `almostultra`) live in `src/styles/themes.css`.
- Icons use Tailwind classes such as `icon-[lucide--search]` and
  `icon-[lucide--plus]`.
- Tailwind scans the templates. Classes assembled at runtime in Rust are
  invisible to the scanner, so list them explicitly with `@source inline(...)` in
  `src/app.css`.
- The formatter intentionally ignores `src/templates/**/*.html` and
  `public/vendored`.

## Vendored assets

`public/vendored/` contains the htmx and htmax distributions used by the
templates. To refresh them, run the devenv script from a devenv shell at the repository
root:

```bash
devenv shell
vendor-download
```

It downloads the pinned versions and creates the `.br` variants used by the
precompressed static file server.

## Troubleshooting

| Symptom                                      | Fix                                                                                  |
| -------------------------------------------- | ------------------------------------------------------------------------------------ |
| `vp: command not found`                      | Install the Vite+ CLI (see Prerequisites) and restart the shell.                     |
| Unstyled pages or 404s under `/static/vite/` | Build with `OUT_DIR=../static/vite`; the server expects that output directory.       |
| Askama says a template is missing            | Run the frontend build before `cargo run`; Askama reads the generated template tree. |
| `vp build` writes to `dist/` unexpectedly    | `OUT_DIR` is unset. Set it to `../static/vite` to match the server.                  |
| Cargo build fails running `devenv tasks …`   | Install devenv or adjust the frontend build invocation in the root `build.rs`.       |
| Type errors after a dependency update        | Run `vp install`, then `vp run build:tsc`.                                           |
| A class emitted by Rust has no styles        | Add it to `@source inline(...)` in `src/app.css`.                                    |
| Template changes do not appear               | Rebuild the frontend; templates are compiled into `static/vite/src/templates`.       |
